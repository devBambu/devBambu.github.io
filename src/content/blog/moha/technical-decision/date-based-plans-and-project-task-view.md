# [의사결정기록] 날짜별 계획을 유지하며 프로젝트별 할 일을 모아 보기

논의 날짜: 2026-10-10 (토)

모하는 날짜를 선택해 할 일을 계획하고 실행 결과를 남기는 앱이다. 할 일을 만들 때 프로젝트를 선택적으로 연결할 수 있다. 날짜를 기준으로 기록하는 흐름은 유지하면서, 여러 날짜에 흩어진 한 프로젝트의 할 일을 모아 볼 방법이 필요했다.

이 글은 화면과 데이터 흐름에 관한 **설계 결정**을 정리한다. 아직 구현이나 사용성 검증을 마친 결과는 아니다.

## 의견

### 기존 프로젝트 관리 화면에 할 일 목록을 넣기

프로젝트 관리 화면에는 이름 변경, 색상 설정, 보관과 삭제처럼 프로젝트 자체를 다루는 기능이 있다. 이곳에 날짜별 할 일 목록까지 넣으면 관리와 기록 조회라는 서로 다른 목적이 한 화면에 섞인다. 목록으로 들어가기 위해 설정 화면을 거쳐야 한다는 점도 고려했다.

### 날짜별 계획 화면을 프로젝트별 보기로 전환하기

기존 계획 화면에서 프로젝트를 선택해 목록을 바꾸는 방식도 검토했다. 하지만 계획을 세우는 기준은 여전히 날짜다. 메인 화면을 프로젝트 중심으로 바꾸면 할 일을 만들 때의 기준과 기록을 찾을 때의 기준이 뒤섞일 수 있다.

### 프로젝트별 조회 화면을 분리하기

프로젝트를 선택하면 그 프로젝트에 연결된 할 일을 날짜별로 보여주는 방식을 선택했다. 프로젝트 화면은 **조회 경로**를 제공하고, 기록 자체는 원래 날짜에 남겨 둔다. 같은 할 일이 날짜별 화면과 프로젝트별 화면에 보이더라도 별도의 기록을 만들지 않는다.

## 결과

합의한 흐름은 다음과 같다.

```text
날짜 선택 → 할 일 생성 → 프로젝트 선택적 연결
프로젝트 선택 → 연결된 날짜별 할 일 조회
조회한 할 일 선택 → 원래 날짜의 기록 편집
```

프로젝트가 연결되지 않은 할 일은 날짜별 계획에서 다룬다. 프로젝트별 목록이 모든 할 일을 관리하는 또 하나의 메인 화면이 되도록 확장하지 않는다.

## 선정 이유

이 방식은 **작성 기준과 조회 기준을 분리**한다. 할 일은 날짜에 속한다는 원칙을 유지하면서, 프로젝트는 여러 날짜의 기록을 찾아보는 관점으로 사용한다. 관리 화면도 프로젝트의 속성을 다루는 역할에 집중할 수 있다.

대신 프로젝트별 조회 화면이 하나 더 필요하다. 두 화면에서 같은 기록을 편집하므로, 구현할 때는 동일한 할 일의 식별과 변경 사항 반영을 보장해야 한다. 어떤 데이터 모델과 조회 방식을 쓸지는 이 결정에 포함하지 않았다. 그 부분은 구현 과정에서 검증할 예정이다.
